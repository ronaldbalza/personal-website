    Data Visualization Rules for Executive Dashboards in Power BI

    An executive gives a dashboard a few seconds before deciding whether it's useful. These are the layout, colour and chart habits that make those seconds count, and how to implement them in Power BI.

    Ronald Balza
    BI Reporting Analyst
    Feb 10, 2026•8 min read

    Most dashboards that fail with senior audiences don't fail because the numbers are wrong. They fail because the reader can't find the answer fast enough. An analyst will happily explore a page with twelve visuals and four slicers; an executive opens it between meetings, looks for one or two numbers, and closes it.

    These are the rules I apply when the audience is leadership. None of them are new, but they're easy to forget once you're deep in DAX.

    1. Start from the question, not the data

    Before opening Power BI Desktop, write down the two or three questions the page has to answer, for example "Are we on track against budget this quarter?" and "Which region is behind?" Every visual on the page should answer one of those questions. If it doesn't, it belongs on a detail page reached through drillthrough, not on the summary.

    2. Put the answer where the eye lands first

    People scan a page from the top left. Use that:

    Keep slicers to the ones leadership actually uses (usually period and business unit) and put them in a consistent place on every page. Hidden filters are worse than visible ones: if a page is filtered, say so in the subtitle.

    3. Never show a number without context

    "Revenue: $4.2M" doesn't tell anyone whether to worry. A KPI needs a comparison: target, prior year or prior period. The built-in KPI visual and the newer card visual both support a reference value; in either case, the comparison measure should be in the model, not calculated by hand.

    I also make the visual title do some of the work. A title that states the finding is read far more often than an axis label. Power BI lets you drive a title from a measure (Format → Title → fx → Field value): 

    Revenue Title =
VAR _yoy = [Sales YoY %]
RETURN
    "Revenue is "
        & FORMAT ( ABS ( _yoy ), "0.0%" )
        & IF ( _yoy >= 0, " ahead of", " behind" )
        & " last year"

    The same technique works for subtitles that show the active filter context, e.g. using SELECTEDVALUE ( 'Region'[Region], "All regions" ).

    4. Choose the simplest chart that answers the question

    QuestionUseAvoid
    How is it trending?Line chart (with target or prior year as a second line)Column charts with 24+ bars
    Which is biggest?Sorted horizontal bar chartPie or donut with more than 3–4 slices
    Are we on target?Card or KPI with variance, bullet-style barGauges that take space for one number
    What drove the change?Waterfall chartStacked columns that make segments hard to compare
    Exact values neededTable or matrix with conditional formattingData labels on every point of a busy chart

    Two specific habits: sort bar charts by value, not alphabetically, and start bar axes at zero. A bar's length is the value; truncating the axis makes small differences look dramatic. (Line charts can use a non-zero axis, because the reader compares slope, not length.)

    5. Use colour to mean something

    The default Power BI palette gives every series a different colour, which is fine for exploration and noisy for executives. A better default: neutral greys for everything, one accent colour for what matters, and red/green reserved strictly for good/bad. Set this once in a report theme so every visual inherits it: 

    {
  "name": "Executive",
  "dataColors": ["#1F6FB2", "#9AA5B1", "#C3CAD2", "#5B6770", "#E2E6EA"],
  "good": "#1A7F37",
  "neutral": "#9AA5B1",
  "bad": "#C62828",
  "background": "#FFFFFF",
  "foreground": "#252423",
  "tableAccent": "#1F6FB2"
}

    Import it from View → Themes → Browse for themes. The good, neutral and bad colours are used by visuals such as the KPI visual and waterfall, and the same hex values can be reused in conditional-formatting rules so variance colours are consistent across pages.

    ⚠️

    Don't rely on colour alone. Red/green is the most common colour-vision deficiency pairing. Add a sign, an arrow icon or a "+/−" in the number format (for example "+0.0%;-0.0%") so the meaning survives without the colour.

    6. Fewer visuals load faster

    This is a usability rule and a performance rule. Each visual on a page generates at least one query against the semantic model, and on DirectQuery models each of those becomes source queries. A page with 25 visuals is slower to render and harder to read. If a page needs that many, it's usually two pages. Performance Analyzer (Optimize ribbon → Performance analyzer) shows how long each visual takes, which is a useful argument when someone asks for "just one more chart".

    7. Make it accessible by default

    • Contrast: aim for at least 4.5:1 between text and background (the WCAG AA level for normal text).
    • Alt text: every visual has an alt text property under General; screen readers use it.
    • Tab order: set it in the Selection pane so keyboard users move through visuals in reading order, and hide decorative shapes from tab order.
    • Mobile layout: if leaders open reports on their phones, build the mobile layout explicitly (View → Mobile layout) with the KPI cards first.

    Wrapping up

    A good executive dashboard is mostly subtraction: one question per page, KPIs with context, the simplest chart for each question and colour that only highlights what matters. Put the decisions into a theme and a set of reusable measures, and every new report starts from a design that already works.
