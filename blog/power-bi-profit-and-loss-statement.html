    Building a Profit & Loss Statement in Power BI

    Finance teams want their P&L to look exactly like the one in the board pack: subtotals in the right places, revenue positive, costs in brackets. A matrix can do it, with the right model behind it.

    Ronald Balza
    BI Reporting Analyst
    Sep 10, 2024•8 min read

    Financial statements are one of the most requested reports in Power BI, and one of the easiest to get wrong. The general ledger gives you thousands of transactions against hundreds of accounts. The finance team wants twenty lines: Revenue, Cost of Sales, Gross Profit, Operating Expenses, EBITDA and so on, with subtotals that aren't stored anywhere in the source.

    The approach below keeps the layout in data (so finance can change it without touching DAX) and uses one measure for every line.

    Step 1 — The model

    Three tables, plus the usual date table:

    • GL: one row per journal line, with Date, AccountCode and Amount. Debits positive, credits negative, a common export convention (if your source differs, adjust the sign in Step 2).
    • Account: the chart of accounts, with a LineID column mapping each account to a P&L detail line. Balance sheet accounts map to their own lines (or none, for a P&L-only model).
    • PL Line: the layout of the statement.
    LineIDLineSortOrderLineType
    10Revenue10Detail
    20Cost of Sales20Detail
    30Gross Profit30Subtotal
    35Gross Margin %35Ratio
    40Employee Costs40Detail
    50Occupancy50Detail
    60Other Operating Expenses60Detail
    70EBITDA70Subtotal
    80Depreciation & Amortisation80Detail
    90EBIT90Subtotal

    Relationships: PL Line[LineID] → Account[LineID] → GL[AccountCode], all one-to-many and single direction, plus Date → GL. Set PL Line[Line] to sort by SortOrder so the matrix shows lines in statement order.

    Step 2 — Get the sign convention right once

    In the ledger, revenue is a credit (negative) and expenses are debits (positive). On a P&L, people expect revenue positive and costs negative so that adding lines down the page gives profit. Flipping the sign of everything does exactly that: 

    GL Amount = SUM ( GL[Amount] )

-- Revenue becomes positive, costs negative: lines now add up to profit
PL Amount = - [GL Amount]

    Because every line is now signed so that it adds up, a subtotal is simply the sum of all detail lines above it. Gross Profit is Revenue + Cost of Sales; EBITDA is everything above line 70, and so on.

    Step 3 — One measure for every line

    P&L Value =
VAR _type = SELECTEDVALUE ( 'PL Line'[LineType] )
VAR _sort = SELECTEDVALUE ( 'PL Line'[SortOrder] )
VAR _subtotal =
    CALCULATE (
        [PL Amount],
        REMOVEFILTERS ( 'PL Line' ),
        'PL Line'[SortOrder] <= _sort,
        'PL Line'[LineType] = "Detail"
    )
VAR _revenue =
    CALCULATE (
        [PL Amount],
        REMOVEFILTERS ( 'PL Line' ),
        'PL Line'[Line] = "Revenue"
    )
RETURN
    SWITCH (
        _type,
        "Detail",   [PL Amount],
        "Subtotal", _subtotal,
        "Ratio",    DIVIDE ( _subtotal, _revenue )
    )

    How it works:

    • On a detail line, the filter on PL Line flows through Account to GL, giving that line's amount.
    • On a subtotal line, no accounts map to it, so we remove the line filter and sum every detail line with a lower sort order.
    • The ratio line (Gross Margin %) divides the running subtotal above it by revenue.
    • On the matrix grand total, no single line is selected, _type is blank and the measure returns blank, which is correct: adding up every line of a P&L, subtotals included, is meaningless. Turn off row totals on the matrix.
    💡

    Formatting the ratio line. One measure returns both currency and percentages. Use a dynamic format string on the measure (Measure tools → Format → Dynamic) such as IF ( SELECTEDVALUE ( 'PL Line'[LineType] ) = "Ratio", "0.0%", "#,##0;(#,##0)" ) so costs show in brackets and margin lines as percentages.

    Step 4 — Budget and prior-year columns

    Because P&L Value only depends on [PL Amount], comparisons are a matter of swapping that base. With a Budget fact mapped to the same accounts, write PL Budget = - SUM ( Budget[Amount] ), copy the pattern as P&L Budget Value, and add variance as the difference. For prior year, wrap the base in SAMEPERIODLASTYEAR, or use a calculation group so the same line logic serves actual, budget and prior year without duplication.

    What changes for a balance sheet

    A P&L shows activity during a period. A balance sheet shows a position at a point in time, so each account's balance is the sum of all transactions up to the end of the selected period: 

    Balance =
VAR _end = MAX ( 'Date'[Date] )
RETURN
    CALCULATE (
        [GL Amount],
        REMOVEFILTERS ( 'Date' ),
        'Date'[Date] <= _end
    )

    This is a semi-additive measure: it adds up across accounts, but not across time. Selecting the year 2024 returns the balance at 31 December 2024, not the sum of twelve month-end balances. If the ledger is large, consider an opening-balance table so the calculation doesn't scan every transaction since the company began. Retained earnings also needs care: current-year profit has to be rolled in so the balance sheet balances.

    Step 5 — Reconcile before anyone sees it

    1. Check that every account with activity maps to a line. A card showing [GL Amount] for accounts with a blank LineID should always read zero.
    2. Match each subtotal to the accounting system's own P&L for at least two closed periods.
    3. Check that the trial balance nets to zero for every period; if it doesn't, the extract is incomplete.

    Wrapping up

    The pattern is a layout table, a consistent sign convention and one measure that knows whether it's on a detail line, a subtotal or a ratio. Finance can reorder lines, add a subtotal or remap an account by editing data, and the report follows without DAX changes. That's what keeps a financial report maintainable after month-end close number twelve.
