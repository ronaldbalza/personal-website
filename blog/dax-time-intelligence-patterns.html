    5 DAX Time Intelligence Patterns Every Power BI Report Needs

    Year-to-date, prior year, YoY growth, rolling 12 months and hiding future dates — the measures that show up in almost every report, and the date table that makes them work.

    Ronald Balza
    BI Reporting Analyst
    Nov 16, 2026•7 min read

    Almost every business question eventually becomes a time question: How are we tracking this year? Are we ahead of last year? What's the trend over the last twelve months? In Power BI, these are answered with DAX time intelligence — and once you have a handful of reliable patterns, you can reuse them on every model you build.

    Below are the five patterns worth keeping in your toolkit. Every example builds on a single base measure: 

    Total Sales = SUM ( Sales[SalesAmount] )

    Before you start: a proper date table

    Time intelligence functions only behave when they have a dedicated date table to work against. Relying on the auto date/time hierarchy or the raw OrderDate column in your fact table is the most common reason YTD numbers come out wrong. 

    Date =
VAR _start = DATE ( YEAR ( MIN ( Sales[OrderDate] ) ), 1, 1 )
VAR _end   = DATE ( YEAR ( MAX ( Sales[OrderDate] ) ), 12, 31 )
RETURN
    ADDCOLUMNS (
        CALENDAR ( _start, _end ),
        "Year", YEAR ( [Date] ),
        "Month Number", MONTH ( [Date] ),
        "Month", FORMAT ( [Date], "MMM" ),
        "Year Month", FORMAT ( [Date], "YYYY-MM" )
    )

    Then make sure the model is set up correctly:

    • The table covers complete years with one row per day and no gaps.
    • It is marked as a date table (Table tools → Mark as date table).
    • It has a one-to-many, single-direction relationship to Sales[OrderDate].
    • Visuals and slicers use columns from 'Date', never from the fact table.
    💡

    Tip: if you have a warehouse such as Snowflake or a Fabric lakehouse, build the date dimension there instead. Every report then shares the same fiscal calendar, holidays and week definitions.

    Pattern 1 — Year-to-date

    DATESYTD returns every date from the start of the year up to the latest date in the current filter context. Wrapping it in CALCULATE gives you a running year-to-date total. 

    Sales YTD =
CALCULATE ( [Total Sales], DATESYTD ( 'Date'[Date] ) )

    Working on a fiscal year? Pass the year-end date as the second argument. For a year ending 30 June: 

    Sales FYTD =
CALCULATE ( [Total Sales], DATESYTD ( 'Date'[Date], "6/30" ) )

    Pattern 2 — Prior year and YoY growth

    SAMEPERIODLASTYEAR shifts the current date selection back exactly one year, so it works at any grain — day, month, quarter or a custom slicer range. 

    Sales PY =
CALCULATE ( [Total Sales], SAMEPERIODLASTYEAR ( 'Date'[Date] ) )

Sales YoY % =
VAR _current = [Total Sales]
VAR _prior   = [Sales PY]
RETURN
    DIVIDE ( _current - _prior, _prior )
    ✅

    Use DIVIDE, not the / operator. It returns blank instead of an error when there's no prior-year value, so new products and first-year periods don't break your visuals.

    Pattern 3 — Rolling 12 months

    Rolling totals smooth out seasonality and are ideal for trend lines. DATESINPERIOD starts at the last visible date and reaches back the number of intervals you specify. 

    Sales Rolling 12M =
CALCULATE (
    [Total Sales],
    DATESINPERIOD ( 'Date'[Date], MAX ( 'Date'[Date] ), -12, MONTH )
)

    Change -12, MONTH to -90, DAY or -4, QUARTER for other windows — the pattern stays the same.

    Pattern 4 — Month-to-date and quarter-to-date

    These follow exactly the same shape as YTD, which is what makes the patterns easy to remember: 

    Sales MTD =
CALCULATE ( [Total Sales], DATESMTD ( 'Date'[Date] ) )

Sales QTD =
CALCULATE ( [Total Sales], DATESQTD ( 'Date'[Date] ) )

    Pattern 5 — Hiding future dates

    Because the date table runs to 31 December, cumulative measures like YTD keep showing the same flat value for every month that hasn't happened yet. That flat line misleads readers. The fix is to blank out any period after the last transaction: 

    Sales YTD (to date) =
VAR _lastSale =
    CALCULATE ( MAX ( Sales[OrderDate] ), ALL ( Sales ) )
RETURN
    IF ( MIN ( 'Date'[Date] ) <= _lastSale, [Sales YTD] )
    ⚠️

    Watch the filter removal. ALL ( Sales ) finds the latest sale across the whole dataset. If you only removed the date filter, a product that stopped selling in March would have its YTD blanked out from April onwards.

    Quick reference

    MeasureKey functionAnswers
    YTD / FYTDDATESYTDHow are we tracking this year?
    Prior yearSAMEPERIODLASTYEARWhat did the same period look like last year?
    YoY %DIVIDEAre we growing?
    Rolling 12MDATESINPERIODWhat's the underlying trend?
    MTD / QTDDATESMTD / DATESQTDWhere are we in the current period?

    Wrapping up

    Get the date table right once, and every one of these measures becomes a two-line CALCULATE. Keep them in a dedicated measure table, give them consistent names, and they'll carry over to every model you build next.

    To apply all of these patterns to any measure without duplicating them, see Calculation Groups in Power BI.
